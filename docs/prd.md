# PRD — 내 주변 관광지·맛집 웹앱

| 항목 | 내용 |
|---|---|
| 문서 상태 | 1단계 확정 + 큐레이션(F-8) 반영 |
| 최종 수정 | 2026-08-30 |
| 플랫폼 | 모바일 웹 (아이폰 Safari 우선) |
| 기술 설계 | [web-nearby-places-design.md](./web-nearby-places-design.md) |

## 1. 배경과 문제

낯선 동네에 있거나 여행 중일 때 "지금 여기서 제일 가까운 볼거리·먹을거리"를 알고 싶은 순간이 있다. 기존 지도 앱으로도 가능하지만 검색어를 입력하고 결과를 훑어 거리를 가늠하는 과정이 필요하다.

이 앱은 **입력 없이, 열자마자, 가까운 순으로** 보여주는 것 하나에 집중한다.

원래 아이폰 네이티브 앱으로 기획했으나 개발 진입 장벽(Xcode·Swift·서명·심사)이 높아 **모바일 웹앱으로 전환**했다. 제품 목표는 그대로이고 구현 플랫폼만 바뀌었다. 중단된 iOS 시도는 `archive/ios-nearby-places/`에 남아 있다.

## 2. 대상 사용자

- 여행지·출장지에서 주변을 빠르게 파악하고 싶은 사람
- 점심 시간에 회사 근처 식당을 찾는 직장인
- 앱 설치를 하기 싫거나 하기 애매한 일회성 사용자 → **웹앱이라는 선택이 여기에 특히 잘 맞는다**

## 3. 핵심 시나리오

> 서울 출장 중인 사용자가 회의 사이 빈 시간에 링크를 연다. 위치 권한을 허용하니 곧바로 반경 1km 관광지가 가까운 순으로 뜬다. "맛집"을 눌러 점심 후보를 확인하고, 결과가 적어 반경을 3km로 넓힌다. 마음에 드는 곳을 눌러 카카오맵 상세 페이지로 이동한다.

## 4. 기능 요구사항 (1단계)

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| **F-1** | 현재 위치 획득 | 페이지 진입 시 자동으로 위치를 요청한다. 권한 허용 시 10초 이내에 좌표를 확보하고, 실패 시 사유(거부/불가/시간초과/비HTTPS)별로 다른 안내를 보여준다. |
| **F-2** | 카테고리별 주변 검색 | 관광지·맛집·카페 세 가지를 탭으로 전환할 수 있다. 전환 즉시 재검색하되 **위치는 다시 잡지 않는다.** |
| **F-3** | 거리순 목록 | 결과는 항상 거리 오름차순이다. 각 항목에 장소명·분류·주소·거리 배지를 표시한다. 배지는 1km 미만이면 `231m`, 이상이면 `1.2km` 형식이다. |
| **F-4** | 반경 조절 | 500m·1km·3km·5km 중 선택한다. 기본값은 1km. 변경 시 위치 재획득 없이 재검색한다. |
| **F-5** | 상세 이동 | 항목을 누르면 카카오맵 장소 상세 페이지를 새 탭으로 연다. 상세 URL이 없는 장소는 링크로 만들지 않는다. |
| **F-6** | 폴백 화면 | 위치 권한 거부 / 앱키 미설정 / 결과 0건 / 검색 실패 각각에 전용 안내 화면을 둔다. 결과 0건일 때는 한 단계 넓은 반경으로 재검색하는 버튼을 제공한다. |
| **F-7** | 새로고침 | 헤더의 버튼으로 위치를 다시 잡아 재검색한다. |
| **F-8** | 직접 정리한 장소 우선 표시 | 씨드 파일로 관리하는 장소를 사진·평점·한줄평과 함께 **위 구획**에, 카카오 실시간 검색 결과를 **아래 구획**에 이어서 보여준다. 각 구획에 출처와 개수를 표시한다. 같은 장소가 양쪽에 있으면 카카오 쪽에서 뺀다. 카카오 검색이 실패해도 큐레이션 결과는 그대로 보여준다. |

### 명시적 비요구사항 (하지 않기로 한 것)

- **카카오 검색 결과는 앱에서 다시 정렬하지 않는다.** 카카오가 거리순으로 정렬해 주고 거리도 계산해 준다.
  (직접 정리한 장소는 좌표만 있으므로 앱이 계산·정렬한다 — F-8)
- 평점·한줄평을 자동 수집하지 않는다. 포털 평점 크롤링은 약관 위반 소지가 있어 직접 입력한다.
- 회원가입·로그인 없음. 서버 없음. 사용자 데이터 저장 없음.

## 5. 비기능 요구사항

| 구분 | 기준 |
|---|---|
| 대상 브라우저 | iOS Safari 16+, Chrome 최신. 데스크톱에서도 깨지지 않을 것 |
| 반응형 | 360px 폭 기준으로 설계. 노치 영역(`safe-area-inset`) 회피 |
| 보안 컨텍스트 | Geolocation 요구사항상 **HTTPS 배포 필수** (localhost는 예외) |
| 성능 | 위치 획득 후 첫 결과까지 3초 이내 목표. 번들·빌드 단계 없음 |
| 접근성 | 탭 버튼에 `role`/`aria-selected`, 결과 영역에 `aria-live`, 거리 배지에 의미를 담은 `aria-label`. 터치 타깃 최소 높이 36px |
| 보안 | 외부에서 온 문자열은 `textContent`로만 렌더링. `innerHTML` 미사용 |
| 다크 모드 | `prefers-color-scheme` 대응 |

## 6. 범위 밖 (2단계 이후)

지도 뷰, 장소 상세 시트, 길찾기 연동, 즐겨찾기, 영업중·가격대 필터, 검색 결과 캐싱, PWA 홈 화면 추가.

## 7. 성공 기준

1. 아이폰 Safari에서 링크를 열고 **위치 허용 한 번 외에 아무 입력 없이** 주변 관광지 목록이 뜬다.
2. 목록이 실제로 가까운 순이고, 거리 표기가 지도 앱과 크게 어긋나지 않는다.
3. 카테고리·반경을 바꿔도 위치 권한을 다시 묻지 않는다.
4. 권한을 거부해도 앱이 흰 화면으로 멈추지 않고 무엇을 해야 하는지 알려준다.

## 8. 제약과 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| iOS Safari에서 위치 권한을 거부하면 웹에서 설정 앱으로 딥링크할 수 없음 | 사용자가 복구 방법을 모름 | 안내 화면에 "설정 → Safari → 위치" 경로를 글로 명시 |
| 카카오 무료 쿼터 정책 변경 이력 있음 (2026-07-21 개정, 계정당 첫 앱만 무료) | 한도 축소 가능 | 현재 로컬 API 일 10만 / 월 300만 건. 정책 공지 주시 |
| JavaScript 앱키가 브라우저에 노출됨 | 타 사이트에서 도용 | 카카오 콘솔의 **사이트 도메인 등록**이 실질 방어선. 미등록 도메인에서는 동작하지 않음 |
| 카카오 `radius` 상한 20km | 시골 지역 결과 0건 | 반경 확대 버튼 제공. 자동 확장은 2단계 |
| `distance`는 직선거리 | 실제 도보 거리와 차이 | 거리 배지의 `aria-label`에 "직선거리" 명시 |
| 큐레이션 데이터가 오래됨 | 폐업한 가게가 남을 수 있음 | 씨드 파일을 주기적으로 손본다. 정보가 정적이라는 점을 감수한 구조다 |
| 평점이 주관적 | 공신력 있는 점수가 아님 | 직접 매긴 점수임을 전제로 한다. 자동 수집 경로가 없다 |
| 실내에서 GPS fix 실패 | 목록이 뜨지 않음 | 10초 타임아웃 후 "실외에서 다시 시도" 안내 |
